# Виджет банковских операций клиента

## Цель и описание проекта:

IT-отдел крупного банка делает новую фичу для личного кабинета клиента.
Это виджет, который показывает несколько последних успешных банковских операций клиента.
Необходимо реализовать проект, который на бэкенде будет готовить данные для отображения в новом виджете.

## Установка:

1. Клонируйте репозиторий:

https://github.com/SandzaBro/HomeWork1.git


## Использование функций:

В проекте реализованно несколько функций:

1. Функция, которая принимает на вход номер карты и возвращает ее маску.
2. Функция, которая принимает на вход номер счета и возвращает его маску.
3. Функция принимает список словарей и опционально значение для ключа state(по умолчанию 'EXECUTED') и возвращает новый список словарей, содержащий только те словари, у которых ключ state соответствует указанному значению.
4. Функция, которая принимает список словарей и необязательный параметр, задающий порядок сортировки (по умолчанию - убывание) и возвращает новый список, отсортированный по дате (date).
5. Функция, которая обрабатывает информацию о картах и счетах.
6. Функция, которая принимает на вход строку с датой в формате "2024-03-11T02:26:18.671407" и возвращает строку с датой в формате "ДД.ММ.ГГГГ"."

# Тестирование

В проекте реализованы тесты для masks.py, processing.py и widget.py, а именно:

1. Для функций get_mask_card_number и get_mask_account:
    - Тестирование правильности маскирования номера карты;
    - Тестирование маскировки разных номеров карт;
    - Тестирование коротких номеров карт;
    - Тестирование некорректных строк; 
    - Тестирование маскировки номера счета; 
    - Параметризованный тест маскировки счетов; 
    - Тестирование некорректных номеров счетов.

2. Для функций filter_by_state и sort_by_date:
   - Тестирование фильтрации со статусом по умолчанию 'EXECUTED'; 
   - Параметризованный тест для разных значений state;
   - Тестирование, когда нет словарей с указанным статусом;
   - Тестирование на пустом списке
   - Тестирование, когда у некоторых словарей отсутствует ключ state;
   - Тестирование, что исходный список не изменяется;
   - Тестирование сортировки по убыванию (по умолчанию);
   - Тестирование сортировки при одинаковых датах (порядок сохраняется);
   - Тестирование на некорректные форматы дат (сортировка по строке);
   - Параметризованный тест для обоих порядков сортировки.

3. Для функций get_date и mask_account_card:
    - Тестирование маскировки различных типов карт;
    - Тестирование маскировки счетов;
    - Тестирование устойчивости к некорректным входным данным;
    - Тестирование корректного преобразования дат;
    - Тестирование работы с разными форматами даты;
    - Тестирование работы с разными разделителями даты;
    - Тестирование обработки некорректных дат;
    - Тестирование стабильности при многократном вызове;
    - Тестирование формата выходной строки;
    - Тестирование работы с различными разделителями даты и времени;
    - Тестирование дат с разным количеством цифр в дне и месяце;
    - Тестирование даты без времени;
    - Тестирование даты с часовым поясом;
    - Тестирование даты с пробелами вместо T.
